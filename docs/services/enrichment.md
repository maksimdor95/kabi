# Модуль: enrichment

## 1. Назначение
Обогащает профиль данными из **собственных публичных источников пользователя**
(по ссылкам, которые он сам дал, и с его согласия): HH-резюме, LinkedIn, записи
выступлений, личный сайт/ТГ-канал. «Менеджер делает домашку, прежде чем спрашивать».

Отличие от `ingestion`: `ingestion` ищет **возможности** (вакансии/CFP) во внешнем мире;
`enrichment` дополняет **профиль самого пользователя** из его же источников.

## 2. Этап
M1 (включено по решению: ENRICH входит в первый срез).

## 3. Публичный интерфейс
```python
class EnrichmentSource(Protocol):
    name: str
    def matches(self, url: str) -> bool: ...
    async def fetch(self, url: str) -> ProfileSignals: ...

async def enrich_from_links(user_id: UUID, links: list[str]) -> ProfileSignals: ...
```
`ProfileSignals` — доп. поля-кандидаты для профиля (темы выступлений, статус поиска,
доп. навыки), которые проходят **подтверждение пользователем** перед записью.

## 4. Входы / Выходы
- **Вход:** список ссылок от пользователя + флаг согласия.
- **Выход:** `ProfileSignals` → в `dialogue_agent` на подтверждение → `profile.update_profile`.

## 5. Зависимости
- **Внутренние:** `app/llm` (извлечение сигналов из текста страниц), `app/services/profile`.
- **Внешние:** `httpx`, парсеры HTML; HH — официальный `api.hh.ru`.

## 6. Данные
Пишет (после подтверждения) в `Profile`: `speaking_topics`, `job_search_status`,
доп. `skills`, `source_links`. См. `docs/architecture/data-model.md`.

## 7. Источники (реалистичность)
| Источник | Как | Ограничение |
|----------|-----|-------------|
| **HH** | публичная страница резюме по ссылке (+ позже API/OAuth) | «сетка НН» как API недоступна |
| **LinkedIn** | каскад обхода login-wall (см. ниже) | **нарушает ToS**; cookie `li_at` — самый надёжный слой |

### LinkedIn: обход login-wall
1. Прямой запрос (browser UA)  
2. Guest-сессия (прогрев cookies + `?trk=public_profile`)  
3. Cookie `LINKEDIN_LI_AT` (+ опц. `LINKEDIN_JSESSIONID`) из браузера пользователя  
4. Google Web Cache  
5. Wayback Machine (последний публичный снимок)  

Если всё упало — честный note, без выдуманных данных.
| **Выступления** | пользователь даёт ссылки → извлекаем темы | автопоиск по имени — только «найти-и-показать-на-подтверждение» |
| **Личный сайт / ТГ-канал** | по ссылке | — |

## 8. Guardrails / ограничения
- **Только источники самого пользователя, с явного согласия** (hard rule №5).
- Никакого автосбора данных о третьих лицах; найденное по имени — только с подтверждением.
- LinkedIn: парсим только по ссылке, которую дал пользователь (его профиль). Осознанное
  нарушение ToS площадки; при login-wall честно сообщаем и не выдумываем данные.
- Все обогащённые поля требуют подтверждения перед записью (сводка в онбординге).

## 9. Тесты / evals
- **Тест:** маршрутизация ссылки к нужному источнику (`matches`).
- **Тест:** LinkedIn auth-wall детектится и не отдаёт выдуманные сигналы.
- **Тест:** извлечение сигналов из фикстуры страницы выступления → темы.
- **Eval:** сигналы не содержат выдуманных/чужих данных (LM-judge).

## 10. Открытые вопросы
- HH: публичный доступ по ссылке vs OAuth-приложение (для MVP — минимально по ссылке).
- Глубина парсинга страниц выступлений (только заголовки/описания vs транскрипты).
- LinkedIn: устойчивость к login-wall — каскад реализован; cookie из браузера
  остаётся самым надёжным fallback.

## 11. Статус
реализован (M1): источники HH / LinkedIn (парсинг) / talks / generic; встроен в онбординг
после шага согласия+ссылок. Автопоиск по имени не делаем (hard rule №5).
LinkedIn ToS нарушаем осознанно (personal MVP, только ссылка пользователя).
