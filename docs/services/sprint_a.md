# Sprint A — первая сессия (staging only)

## Цель
Новичок за ≤3 мин доходит до полезных карточек без обязательного PDF.
Прод не трогаем, пока нет явного «Ок» на выкладку.

## A1. Старт без PDF + точечные вопросы
Вход: PDF **или** текст (роли/опыт) **или** полезная ссылка (HH/LinkedIn).
После сида профиля шаги:
1. `confirm_roles` — подтвердить/поправить роли из CV/текста
2. `focus_aim` — сферы/компании (кнопки-подсказки + свободный текст → `goals`)
3. далее как было: ссылки → приоритет → ЗП → куда не (`hard_nos`)
4. `level` — только если в ролях нет Middle/Senior/Lead/Head/CPO (skip иначе)

Не спрашиваем закрытый B2B/B2C. Вертикали — быстрые кнопки, не таксономия.

## A2. Сразу подборка + `digest_limit`
После `finished` онбординга бот сам шлёт jobs-подборку.
Лимит карточек: `digest_schedule.digest_limit` (дефолт **3**, 1–10).
Один лимит для `/today`, `/pitch` pending, auto-digest, Mini App default, watch batch.
Интерактивный сбор: `jobs_mode=fast` (без TG/career); полный — у scheduler.

## A3. Soft-fail
Пусто → честный empty_state (уже есть). Reason при 429 → шаблон (уже есть).
Сообщения «собираю…» без ложного «готово».

## A4. Меньше поверхностей
Reply-меню: только Вакансии + Профиль (+ Избранное).
Бургер: start, today, profile, schedule, saved, delete (+ pitch/talks остаются, но не в reply).
Mini App: не дублировать промо на каждый `/start`, если Menu Button уже есть.

## A5. Воронка
События: `session_started`, `entry_chosen`, плюс существующие onboarding/cv/digest/react.
Спека воронки в `analytics.md`. Отчёт: `scripts/funnel_report.py`.

## Статус
`готово на staging` — прод только после явного «Ок»
