# Модуль: bot

## 1. Назначение
Интерфейс Telegram: принимает ввод пользователя и рендерит вывод. **Тонкий слой** —
вся бизнес-логика в `app/`. Бот только маршрутизирует и форматирует.

## 2. Этап
M1 (базовые хендлеры), дозревает на каждом этапе (кнопки фидбека — M2, дедлайны — M3).

## 3. Публичный интерфейс
- `bot/main.py` — точка входа: инициализация `aiogram`, регистрация роутеров, polling,
  запуск планировщика (`start_scheduler`).
- `handlers/` — по хендлеру на сценарий: `start`, `cv`, `chat`, `digest` (команды `/today`,
  `/saved` и колбэки `fb:<action>:<match_id>`), `profile` (`/profile`, `/schedule`,
  `/delete` с подтверждением `profile_del:*`).
- `keyboards/` — рендер карточки (`format_card`: работодатель bold, ЗП, выжимка
  «Суть», «Почему ты»; **title/org причёсываются** через
  `app/ingestion/normalize_job` — питч компании не в bold-заголовке;
  хвост «Темы: …» из старых записей не показываем;
  источник не акцентируем), меню по `priorities`
  (`main_menu_keyboard` / `menu_for_profile`), инлайн-кнопки реакций
  («🔖 Избранное», «🙈 Скрыть», «✍️ Сопроводительное»),
  reply-клавиатура шагов онбординга, подтверждение удаления профиля.
  Подпись ссылки честная: `link_label` из digest — `Открыть страницу заявки →`
  только для реального CFP (`meta.cfp_url`), иначе `Открыть сайт →`.
  Кнопки: «Вакансии» / «СМИ и подкасты» / «Конференции» (не жаргон Питч/CFP).
- `draft:` — берёт профиль по `Match.profile_id` через `session.get(Profile, ...)`
  (не по `user_id`), генерит сопроводительное / питч.
- `profile_del:yes` / `profile_del:no` — подтверждение полного удаления аккаунта
  (`profile.delete_account`).
- `middlewares/` — общий контекст (user, сессия), логирование, троттлинг.

## 4. Входы / Выходы
- **Вход:** сообщения, документы (CV), нажатия инлайн-кнопок.
- **Выход:** вызовы сервисов `app/services/*`; ответные сообщения/карточки.

## 5. Зависимости
- **Внутренние:** `app/services/dialogue_agent`, `app/services/profile`,
  `app/services/digest`, `app/services/feedback`.
- **Внешние:** Telegram Bot API через `aiogram`.

## 6. Данные
Прямо в БД не пишет. Работает через сервисы. Может держать легкое состояние диалога в Redis.

## 7. Конфиг (env)
| Переменная | Назначение |
|------------|------------|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather (не коммитить) |

## 8. Guardrails / ограничения
- **Никакой бизнес-логики** (hard rule №1). Только маршрутизация и рендер.
- Не хранит секреты; токен из env.
- Ограничение размера/типа загружаемого CV (PDF/DOCX, лимит МБ).

## 9. Тесты / evals
- Хендлеры вызывают правильные сервисы с правильными аргументами (моки сервисов).
- Рендер карточки возможности соответствует ожидаемому формату.

## 10. Открытые вопросы
- Long polling или webhook для MVP? (для single-user — polling проще).

## 11. Статус
M1+M2+M3+M4: `start`, `cv`, `chat`, `digest` (`/today`, `/pitch`, `/saved`, `/talks`;
тихий алиас `/deadlines` не в меню команд), `profile` (`/profile`, `/schedule`, `/delete`),
реакции `fb:*`, кнопка «✍️ Сопроводительное» (`draft:`), обучение эмбеддинга на 👍/👎.
`/delete` — подтверждение инлайн-кнопками, затем полный wipe аккаунта.

Потоки подборки (не мешать):
- `/today` — вакансии
- `/pitch` — СМИ/подкасты для питча (без выдуманных дедлайнов)
- `/talks` — конференции с известной датой подачи заявки спикера

`/today` и `/pitch`: сначала проверка `ready_for_matching`, статус «собираю…»
только если профиль готов. Иначе — отказ + текущий шаг онбординга (кнопки),
без ложного «ищу вакансии».

После CV mid-онбординга — короткий ack без переспроса того же шага (PDF и ссылка
отдельными сообщениями не плодят «бубль» профиль/ссылки/приоритет).
Меню: «🔎 Вакансии» · «🎙️ Питч» · «🎤 CFP» · «🔖 Избранное» · «👤 Профиль».
`/deadlines` в BotFather-меню не светим.
