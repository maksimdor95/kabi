# Модуль: observability

## 1. Назначение
Наблюдаемость харнесса: структурные логи, трейсы прогонов агента, учёт токенов и
стоимости LLM. Без неё нельзя понять, работает агент хорошо или «тихо дрейфует».

## 2. Этап
M1 (логи + учёт токенов), дозревает с ростом системы.

## 3. Публичный интерфейс
```python
def get_logger(name: str) -> Logger: ...
def track_llm_usage(model: str, prompt_tokens: int, completion_tokens: int) -> None: ...
# контекст-менеджер трейса прогона (pipeline run / диалоговый шаг)
```

## 4. Входы / Выходы
- **Вход:** события из модулей (LLM-вызовы, прогоны scheduler, ошибки).
- **Выход:** логи/метрики (stdout структурно; позже — экспорт).

## 5. Зависимости
- **Внутренние:** используется всеми модулями.
- **Внешние:** логирование; (позже) трейсинг/метрики.

## 6. Данные
Не владеет доменными сущностями; может писать лог-записи прогонов.

## 7. Guardrails / ограничения
- Не логировать секреты и чувствительные персональные данные пользователя.
- Учёт стоимости — обязателен для контроля OpEx токенов.

## 8. Тесты / evals
- **Тест:** учёт токенов агрегируется корректно по модели/периоду.

## 9. Открытые вопросы
