# Kabi — персональный AI-менеджер карьеры

Персональный AI-агент в Telegram, который знает о пользователе всё релевантное для
карьеры и **проактивно** приносит подходящие вакансии и приглашения на выступления —
как персональный менеджер у звезды.

## Идея в одном абзаце

Обычные джоб-сайты пассивны: ищешь и фильтруешь ты сам. Kabi работает наоборот — как
менеджер звезды: сам находит возможности, отсеивает шум и приносит только «твоё»,
объясняя «почему это про тебя».

## Статус

**Сделано:** M1–**M11** + **MU-A** + **Pitch 2.0** (сид, карточка «Как зайти», shown/org cooldown).

**Дальше:** P1 product_events → P2 UX онбординга → P3 jobs parity. Бэклог — в конце файла.

> (контракт качества до расширения воронки). В таблице ниже — статусы, не очередь.

| **M8** | Evals: подборка + «почему ты» — [`docs/services/evals.md`](docs/services/evals.md) | ✅ |

| **M10** | Alembic вместо `create_all` + ручных `ALTER` | ✅ |
| **MU-A** | Изоляция N Telegram-профилей в одном боте — [`multiuser.md`](docs/services/multiuser.md) | ✅ |
| **M11** | Telegram Mini App: подборки, избранное и профиль экраном — [`miniapp.md`](docs/services/miniapp.md) | ✅ |

**Гипотеза M6:** готового API/маркетплейса открытых CFP под product/RU нет —
значит, умение **сам находить и копить** CFP по карте и нише — рыночный актив,
а не «дописать yaml».

**Вне scope (уровень B / продукт):** SaaS-тенанты, биллинг, success fee, сбор данных о третьих лицах.
Несколько людей в одном боте (ты + жена) — это MU-A, уже в scope.

## Структура репозитория

```
Kabi/
├── AGENTS.md              # правила/харнесс проекта (читать первым)
├── SPEC.md                # продуктовая спецификация MVP
├── docs/
│   ├── architecture/      # overview, ADR, модель данных
│   └── services/          # по одному MD на каждый модуль
├── bot/                   # Telegram-интерфейс (тонкий слой)
├── app/                   # ядро: агент, домен, инфраструктура
│   └── api/               # HTTP для Mini App (тоже тонкий слой)
├── web/                   # статика Mini App (HTML/CSS/JS без сборки)
├── deploy/                # Caddyfile для HTTPS
└── tests/                 # тесты и evals
```

## Как ориентироваться

1. Прочитай `AGENTS.md` — правила и hard rules.
2. `docs/architecture/overview.md` — карта системы и границы модулей.
3. `docs/services/<module>.md` — спека конкретного модуля.

## Локальный запуск (заготовка)

```bash
cp .env.example .env   # заполнить токены
docker compose up -d   # postgres + redis
PYTHONPATH=. python scripts/migrate.py ensure
# запуск бота
PYTHONPATH=. python -m bot.main
# Mini App: API + статика (отдельный процесс)
PYTHONPATH=. uvicorn app.main:app --port 8080
```

Локально Mini App показывает заглушку: Telegram отдаёт `initData` только внутри
клиента и только по HTTPS. Чтобы открыть его по-настоящему — нужен домен с
сертификатом (`deploy/Caddyfile`) и `MINIAPP_URL` в `.env`.
См. [`docs/services/miniapp.md`](docs/services/miniapp.md).
